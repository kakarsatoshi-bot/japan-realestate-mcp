description: セッションの状態サマリーを固定フォーマットで出力し、引き継ぎ書等に書き込んでコミット・プッシュする
---

このセッションでの作業内容を、以下の3項目でまとめること：

```
* やったこと：（1〜2行）
* 効果（数字で）：（Before→After。数値化できなければ「変化なし」「効果測定はまだ」と明記）
* 次回：（次にやることを1つに絞れるなら1つ、選択肢があれば明示。判断待ちなら「要判断：〜」）
```

手順：

1. このリポジトリの「現在の状態」を書き込む場所を特定する：
   - `handover/`配下に`*引き継ぎ書*.md`のようなバージョン別ファイル群があれば、そのうち最新バージョンのファイルが対象。セクションはファイル冒頭（タイトル行の直後、`前バージョン：`等のメタ情報より前）に挿入・上書きする
   - 無ければ、CLAUDE.mdまたはREADME.mdの中に「現在の状態」または「実装状況」という見出しの節があればそこを使う。無ければCLAUDE.mdの末尾に新設する
2. そこに以下の形式で書き込む（既存の同見出しがあれば内容を置き換える。上書き更新であり追記ではない）：
   ```
   ## 現在の状態（最終更新：YYYY-MM-DD）
   - やったこと：...
   - 効果（数字で）：...
   - 次回：...
   ```
3. 変更をコミットする。作業中のブランチに他の変更が既にあればそこに含めてコミットしてよい。このセッションで他に変更が無く、かつ現在のブランチがまだリモートにpushされていない・PRが無い場合は、この更新用に新しいブランチを切り、コミットし、pushして、ドラフトPRを作成する（タイトル例：「状態サマリー更新」）。既にPRがある場合はそのブランチにコミットしてpushするだけでよい（追加PRは作らない）。
4. 上記1〜3を実行したら、ユーザーに向けて3項目のサマリーを出力する。
5. 続けて、このセッションで仕組み（ワークフロー・スクリプト・スキーマ等、他へ影響しうる変更）に変更を加えたかどうかを一言で報告する。該当する場合は「この内容を引き継ぎ書に新バージョンとして記録しますか？」とユーザーに確認する。**記録するかどうかはユーザーの判断に委ね、確認なしに詳細な引き継ぎ書を書き起こさないこと**。ユーザーが記録を希望した場合のみ、このリポジトリのCLAUDE.mdにある引き継ぎ書運用ルールに従って詳細な新バージョンを作成する。仕組み変更が無かった場合は「記録対象の仕組み変更なし」とだけ伝え、確認は不要。
